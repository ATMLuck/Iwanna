# 架构总览

> 类 I Wanna 2D 横板跑酷游戏 · Unity 2022 / Windows
> 本文是整体分层与核心约定的入口，子主题见 [[00-索引]]。

## 1. 设计原则

1. **单一入口**：游戏运行期只有一个核心协调者 `GameManager`，组件不互相调用，只向上"通知"。
2. **组件只通知、不决策**：尖刺/存档点/按钮/终点等组件，触发时只发出事件；由 `GameManager` 决定状态变化。
3. **Manager 常驻**：跨场景存活的逻辑（游戏状态、音频、进度）放入 `DontDestroyOnLoad` 的常驻对象。
4. **组件 Prefab 化**：可复用玩法组件做成"拖进场景即用"的 Prefab + 脚本，参数走 Inspector。

## 2. 分层结构

```
┌─ 场景层 ────────────────────────────────────┐
│  MainMenu（主菜单：主界面/设置/团队介绍/选关）  │
│  Level_01 … Level_03（每关一个场景）         │
├─ 组件层（可复用 C# 组件） ────────────────────┤
│  尖刺 · 存档点 · 按钮 · 终点 · 子弹 · 玩家     │
├─ 管理器层（常驻单例） ────────────────────────┤
│  GameManager(核心状态机) · EventCenter       │
│  AudioManager · ProgressManager · UIManager│
├─ 数据层 ────────────────────────────────────┤
│  JSON 配置文件（关卡解锁进度、音乐列表等）      │
└────────────────────────────────────────────┘
```

## 3. 核心模块清单

| 模块 | 职责（一句话） | 归属 |
|---|---|---|
| `GameManager` | 关卡状态机 + 总协调（进行中/暂停/死亡/通关/下一关） | A:核心逻辑负责人 |
| `EventCenter` | 轻量事件中心，组件发事件、管理器订阅 | 与 GameManager 同人维护 |
| `AudioManager` | 背景音乐/音效播放，音量调节、切换 BGM | B:音频+存档负责人 |
| `ProgressManager` | 读写 JSON：关卡解锁进度、设置项 | B:音频+存档负责人 |
| `UIManager` | 界面切换（主菜单、HUD、暂停、通关提示） | C:UI负责人 |
| 组件层 | 尖刺/存档点/终点（只通知）、子弹（哑弹，只飞行） | E:组件脚本负责人 |
| 关卡局部 | 按钮/机关（门/移动平台），只做关卡内联动 | F:关卡设计人 |
| 玩家控制器 | 移动/跳跃/朝向/射击/死亡动画 | D:玩家控制器负责人 |

## 4. 通信约定

- **组件 → GameManager**：通过 `EventCenter` 发事件（如 `EventCenter.Broadcast(GameEvent.PlayerDeath)`），组件**不需要持有 GameManager 引用**。
- **GameManager → 其他 Manager**：GameManager 作为协调者，调用 `AudioManager` / `UIManager` / `ProgressManager` 的公开方法，或同样走事件。
- **按钮/机关例外**：按钮是关卡局部逻辑，直接引用目标机关，**不产生全局事件、GameManager 不参与**（见 [[玩法系统规范]]）。

> 事件中心把"组件只通知"落实为统一约定。详见 [[代码与命名规范]]。

## 5. 数据流示例（死亡）

1. 玩家碰到尖刺 → 尖刺组件发 `PlayerDeath` 事件。
2. `GameManager` 收到 → 死亡次数 +1 → 触发死亡动画 → 回到出生点/最近存档点。
3. `GameManager` 通知 `UIManager` 刷新右上角死亡次数。
