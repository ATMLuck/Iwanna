# 代码与命名规范

> 团队统一的代码约定，避免集成冲突。整体见 [[架构总览]]，分工见 [[开发分工]]。

## 1. 事件中心定案（核心）

采用 **`GameEvent` 枚举 + 静态 `EventCenter`**（不用字符串 Key）。组件只 `Broadcast`，管理器 `Subscribe`。

**为什么用枚举**：编译期检查、拼写错误直接报错、IDE 自动补全、重命名安全；字符串 Key 灵活但易错，一周新手项目用枚举更稳。

```csharp
// 事件清单（按需增补，禁止新建语义重叠的事件）
public enum GameEvent {
    PlayerDeath,        // 玩家死亡
    PlayerRespawned,    // 玩家重生完成
    SavePointReached,   // 触碰存档点
    LevelComplete,      // 到达终点通关
    DeathCountChanged,  // 死亡次数变化
    TimerTick,          // 计时
    Pause, Resume       // 暂停/恢复
}
```

> 完整广播/订阅讲解与代码示例见 [[事件中心与广播订阅示例]]。

### 1.1 参数约定表

| 事件 | arg 类型 | 广播方 | 订阅方 |
|---|---|---|---|
| `PlayerDeath` | `null` | 尖刺 / 掉落等 | GameManager |
| `PlayerRespawned` | `null` | GameManager | 关卡局部逻辑（需重置的机关） |
| `SavePointReached` | `Vector3`（存档点位置） | SavePoint | GameManager |
| `LevelComplete` | `null` | Goal | GameManager |
| `DeathCountChanged` | `int`（当前死亡次数） | GameManager | UIManager(HUD) |
| `TimerTick` | `float`（累计秒） | GameManager | UIManager(HUD) |
| `Pause` / `Resume` | `null` | GameManager | 各需响应的对象 |

> **按钮是关卡局部逻辑**：不产生全局事件，按钮直接调用目标机关（见 [[玩法系统规范]] 第 3 节），不进上表、GameManager 不参与。

### 1.2 订阅/退订细则（按对象生命周期分两种）

- **常驻 Manager**（GameManager / UIManager / AudioManager）：`Awake()` 订阅一次即可，生命周期 = 整个游戏，**不需要退订**。
- **临时对象**（场景内、会被销毁的）：`OnEnable()` 订阅、`OnDisable()` 退订，避免重复订阅和已销毁对象收到事件。
- **只广播不订阅的组件**：存档点 `SavePoint`、终点 `Goal`（无需复位，无生命周期问题）。
- **需复位的一次性机关**：尖刺 `Spike`、按钮/门/移动平台 —— 订阅 `PlayerRespawned` 复位自身，按临时对象规则 `OnEnable` 订阅 / `OnDisable` 退订。

### 1.3 注意事项

1. **广播方先做去重**：尖刺 `OnTriggerEnter2D` 可能多次触发，组件侧要加一次性标记（如 `isTriggered`），不能靠事件中心去重。
2. **handler 内不抛异常**：`Broadcast` 是多播委托一次性调用，一个 handler 抛异常会中断后续 handler。
3. **新增事件流程**：先在 `GameEvent` 追加 → 在 1.1 参数表补一行 → 避免语义重叠（已有 `PlayerDeath` 就不再新增 `PlayerDie`）。

## 2. 目录结构规范

```
Assets/
├─ Scenes/                场景文件（MainMenu、Level_01 … Level_03）—— 关卡场景归F:关卡设计人
├─ Scripts/
│   ├─ Managers/          常驻管理器（GameManager、EventCenter → A:核心逻辑负责人；AudioManager、ProgressManager → B:音频+存档负责人）
│   ├─ Player/            PlayerController —— D:玩家控制器负责人
│   ├─ UI/                UIManager + 主菜单/HUD/暂停/通关 UI 脚本 —— C:UI负责人
│   ├─ Level/             按钮、机关（门/移动平台）等关卡局部逻辑脚本 —— F:关卡设计人
│   └─ Component/         可复用玩法组件（Spike、SavePoint、Goal、Bullet）—— E:组件脚本负责人
├─ Prefabs/
│   ├─ Player/            Player.prefab —— D:玩家控制器负责人
│   ├─ UI/                各 UI Prefab —— C:UI负责人
│   ├─ Level/             按钮/机关 Prefab —— F:关卡设计人
│   └─ Component/         尖刺/存档点/终点/子弹 Prefab —— E:组件脚本负责人
├─ Audio/                 BGM/、SFX/ —— B:音频+存档负责人
├─ Data/                  JSON 配置文件（config.json 模板），由 ProgressManager 读写 —— B:音频+存档负责人
└─ Art/
    ├─ Environment/       地图组件相关贴图、背景等 —— C:美术（G 协助）
    └─ Animation/         角色各状态图集动画 —— C:美术（G 协助）
```

> 加载约定：不使用 `Resources` 动态加载，组件/UI 一律以 Prefab 形式在场景里拖引用。

**目录 → 负责人对照**：

| 目录                   | 作用                                                          | 负责人          |

## 3. C# 命名规范

| 类型          | 规则                       | 示例                                                |
| ----------- | ------------------------ | ------------------------------------------------- |
| 类 / 方法 / 属性 | PascalCase               | `PlayerController`、`OnPlayerDeath()`              |
| 变量 / 参数     | camelCase                | `deathCount`、`moveSpeed`                          |
| 私有字段        | 下划线 + camelCase          | `_deathCount`                                     |
| 常量          | UPPER_SNAKE_CASE         | `JUMP_FORCE`                                      |
| 枚举值         | PascalCase               | `GameEvent.PlayerDeath`                           |
| 布尔变量        | `is` 前缀为主，`has`/`can` 酌情 | `isTriggered`、`isDead`、`hasDoubleJump`、`canShoot` |
| 事件回调方法      | `On` + 事件名               | `OnPlayerDeath`、`OnSavePoint`                     |
| 场景名         | `Level_` + 补零序号          | `Level_01`、`Level_02`                             |
| Prefab 名    | 与类名一致                    | `Spike.prefab`                                    |
|             |                          |                                                   |

- **不使用命名空间（namespace）**：组件名全局唯一，避免 `using` 混乱。
- 组件脚本统一命名：
  - `Component/`：`Spike`、`SavePoint`、`Goal`、`Bullet`
  - `Level/`：`ButtonTarget`、`Door`、`MovingPlatform`
  - `Player/`：`PlayerController`

## 4. 输入键位常量（集中定义）

禁止散写 `KeyCode` 或字符串魔法值，统一到 `InputDef`：

```csharp
public static class InputDef {
    public const string Horizontal = "Horizontal"; // 移动轴，用 Input.GetAxisRaw 读取（无平滑，更跟手）
    public const KeyCode Jump  = KeyCode.Space;    // 跳跃（二段跳）
    public const KeyCode Shoot = KeyCode.J;        // 发射子弹
    public const KeyCode Pause = KeyCode.Escape;   // 暂停/返回主菜单
}
```

- **移动读取**：`Input.GetAxisRaw(InputDef.Horizontal)`（不用 `GetAxis`，避免平滑惯性）。
- **输入系统**：固定使用 Unity 旧版 Input Manager（默认已配好 `Horizontal` 轴），**不要**切换到 Input System 新包。

## 5. 单例写法（Manager 基类）

```csharp
public class Singleton<T> : MonoBehaviour where T : MonoBehaviour {
    public static T Instance { get; private set; }
    protected virtual void Awake() {
        if (Instance != null && Instance != this) { Destroy(gameObject); return; }
        Instance = this as T;
        DontDestroyOnLoad(gameObject);
    }
}
```
对于Manager管理层，Unity新建默认脚本会继承MonoBehaviour类。此时对自行编写的Manager管理层类（GameManager，UIManager，AudioManager，ProgressManager），无需继承MonoBehaviour，将默认的MonoBehaviour类修改为泛型类`Singleton<T>`（T为自己的类名，如`public class AudioManager : Singleton<AudioManager> { /* ... */ }`)
继承该基类将会自动添加Instance方法，判重，DontDestroyOnLoad。

- **用单例的**：`GameManager`、`AudioManager`、`ProgressManager`、`UIManager`（均继承 `Singleton<T>`，挂 `Bootstrap` 空物体）。
- **不用单例的**：`EventCenter`（静态类，不挂物体）、`PlayerController`、各玩法组件。
- 订阅/退订约定见 1.2 节（不在此重复）。

## 6. Tag / Layer 约定

### 6.1 Tag（只加一个）

| Tag | 用途 |
|---|---|
| `Player` | 唯一必须的 Tag；尖刺/存档点/终点用 `CompareTag("Player")` 识别玩家 |

- 禁止 `gameObject.name == "Player"` 字符串比对（重命名即坏）。

### 6.2 Layer 详细规定（需在 `Edit > Project Settings > Tags and Layers` 创建）

| Layer | 层名 | 挂载物体 | Rigidbody2D | Collider2D | isTrigger | 说明 |
|---|---|---|---|---|---|---|
| 8 | `Player` | Player | Dynamic（受重力） | Box / Capsule | 否 | 玩家本体 |
| 9 | `Ground` | 地形（地面/墙/平台） | 无（静态） | Box / Edge / Tilemap+Composite | 否 | 实心，供站立与挡子弹 |
| 10 | `Damage` | Spike | 无（静态） | Box / Polygon（贴合尖刺） | **是** | 触碰即死 |
| 11 | `Bullet` | Bullet | Dynamic（`gravityScale=0`） | Box / Circle | 否 | 直线飞行 |
| 12 | `Button` | ButtonTarget | 无（静态） | Box | **是** | 被子弹命中触发 |
| 13 | `Trigger` | SavePoint、Goal | 无（静态） | Box / Circle | **是** | 被玩家触碰触发 |

> - 层号（8–13）只是建议，重点是**层名统一**；代码一律用 `LayerMask.NameToLayer("Player")` 获取，禁止硬编码数字。
> - **地面检测**：Player 下挂 `GroundCheck` 空子物体（留在 `Player` 层），用 `Physics2D.OverlapCircle(groundCheck.position, radius, groundLayerMask)` 判断是否着地，`groundLayerMask` 只勾 `Ground`。

### 6.3 Physics2D 碰撞矩阵（只勾选以下层对）

| 层对 | 交互类型 | 决定因素 | 说明 |
|---|---|---|---|
| Player ↔ Ground | 碰撞 | 双方均非触发 | 玩家站立 |
| Player ↔ Damage | 触发 | Damage 是触发 | 尖刺即死 |
| Player ↔ Trigger | 触发 | Trigger 是触发 | 存档点/终点 |
| Bullet ↔ Ground | 碰撞 | 双方均非触发 | 子弹撞墙销毁 |
| Bullet ↔ Button | 触发 | Button 是触发 | 子弹命中按钮 |

- 其余层对**全部不勾选**（Player↔Bullet、Player↔Button、Bullet↔Damage、Damage↔Ground 等），减少无用回调。
- **原理提醒**：矩阵勾选 = 这两层"可以交互"；是"碰撞"还是"触发"由碰撞体的 `isTrigger` 决定；且至少一方有 Rigidbody2D 才会产生回调。
- 逐步骤配置说明见 [[碰撞矩阵配置说明]]。
