# 场景与流程规范

> 场景组织与游戏流程约定。整体分层见 [[架构总览]]。

## 1. 场景清单

| 场景名 | 内容 | 负责人 |
|---|---|---|
| `MainMenu` | 主菜单（主界面 / 设置 / 团队介绍 / 选关），纯 UI 单场景 | C:UI负责人 |
| `Level_01` … `Level_03` | 每关一个场景（地图 + 组件 + 玩家 + HUD） | F:关卡设计人 |

- 通关 UI、暂停界面、HUD 作为**关卡场景内的 UI**，不单独建场景。

## 2. 常驻对象（跨场景存活）

- `GameManager`、`EventCenter`、`AudioManager`、`ProgressManager` 挂在 `Bootstrap` 空物体上，`DontDestroyOnLoad`。
- **初始化规则**：`Bootstrap` 只在 `MainMenu` 场景存在；进入关卡场景时检测"若已存在则不重复创建"，避免多实例。
- 玩家、HUD **不跨场景常驻**：每关场景各自放 `Player` + HUD Prefab。

> 广播/订阅（EventCenter）机制与完整代码示例见 [[事件中心与广播订阅示例]]。

## 3. 游戏流程

```
MainMenu（主菜单）
   ├─ 选关 → Level_XX（已解锁）
   ├─ 设置 → 调音量 / 换 BGM
   ├─ 团队介绍
   └─ 退出游戏
Level_XX
   ├─ 暂停(Esc/按钮) → 重新挑战 / 继续 / 返回主菜单
   ├─ 死亡 → 死亡动画 → 出生点/最近存档点
   ├─ 到达终点 → 通关提示 → 下一关（非最后一关）
   └─ 到达终点（最后一关）→ 通关 UI → 返回主菜单
```

### 3.1 场景切换调用链（UI → GameManager）

**原则**：场景切换（选关 / 下一关 / 重开 / 返回主菜单）**统一由 `GameManager` 执行**，UI 只发指令、不直接 `SceneManager.LoadScene`。

**选关示例**：
1. 选关界面点击"第 N 关"按钮 → UI 脚本调用 `GameManager.Instance.LoadLevel(N)`。
2. `GameManager.LoadLevel(N)` 内部：
   - 恢复 `Time.timeScale = 1`（防残留暂停）；
   - 记录 `currentLevel = N`、重置计时/死亡次数、`lastSavePoint = spawnPoint`；
   - 检查 `ProgressManager.IsLevelUnlocked(N)`（未解锁则提示）；
   - `SceneManager.LoadScene("Level_0N")`。

**GameManager 对外关卡流 API（供 UI 调用）**：

| 方法 | 用途 |
|---|---|
| `LoadLevel(int n)` | 选关 / 进入关卡 |
| `RestartLevel()` | 暂停菜单"重新挑战" |
| `ResumeGame()` | 暂停菜单"继续" |
| `BackToMainMenu()` | 暂停 / 通关返回主菜单 |
| `PauseGame()` | 暂停（Esc / 暂停按钮） |

> UI 是"主动方"，与玩家一样直接调用 `GameManager.Instance` 的公开方法；被动组件（尖刺/存档点/终点）才走事件中心。

## 4. 暂停与时间冻结

- 暂停：`Time.timeScale = 0`；恢复：`Time.timeScale = 1`。
- 暂停界面自身动画/输入需用 `Time.unscaledDeltaTime`，否则被冻结。
- 返回主菜单前必须先恢复 `Time.timeScale = 1`，防止主菜单卡死。

## 5. 输入约定（统一）

| 键 | 作用 |
|---|---|
| 方向键 / A D | 左右移动 |
| 空格 / 其它 | 跳跃（二段跳） |
| `J` | 发射子弹 |
| `Esc` | 主菜单/关卡内返回或暂停 |

> 输入键位需在 [[代码与命名规范]] 中以常量统一定义，禁止散写魔法按键。
