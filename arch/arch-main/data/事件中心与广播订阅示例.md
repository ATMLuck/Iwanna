# 事件中心与广播订阅示例

> **广播/订阅（发布-订阅）**机制 + `EventCenter` 示例。
> 是 [[代码与命名规范]] 第 1 节的配套教程；事件清单与参数约定表以 [[代码与命名规范]] 为准。

## 1. 什么是"广播/订阅"

**生活例子**：广播电台 ↔ 收音机。电台不知道谁在听，谁想听就调到这个频率；电台只负责发信号，听众自己决定要不要接收。

**游戏里对应**：

- **广播方（发布者）**：尖刺、存档点、终点等组件，出事了"喊一嗓子"，**不关心谁来处理**。
- **订阅方（订阅者）**：`GameManager`、`UIManager` 等，提前"登记"想听哪些事件，收到后自己处理。

**好处**：组件不需要持有 `GameManager` 的引用，7 个人可以并行开发、互不依赖——这就是本架构"组件只通知、不决策"的落地方式。

## 2. 三件套

| 组成 | 作用 |
|---|---|
| `GameEvent` 枚举 | 列出所有事件类型（"喊话"的种类） |
| `EventCenter` 静态类 | 负责登记订阅者、分发事件 |
| 参数约定表 | 规定每个事件 `arg` 传什么类型（见 [[代码与命名规范]] 1.1） |



## 4. 广播方示例：尖刺 `Spike`

```csharp
using UnityEngine;

public class Spike : MonoBehaviour {
    bool _triggered = false;  // 一次性标记，防止 OnTriggerEnter2D 连续触发

    void OnEnable()  { EventCenter.Subscribe(GameEvent.PlayerRespawned, OnRespawn); }
    void OnDisable() { EventCenter.Unsubscribe(GameEvent.PlayerRespawned, OnRespawn); }

    void OnTriggerEnter2D(Collider2D other) {
        if (_triggered) return;                  // 已触发过就不再广播
        if (!other.CompareTag("Player")) return; // 只关心玩家

        _triggered = true;
        // 只广播，不处理重生/计数 —— "组件只通知"
        EventCenter.Broadcast(GameEvent.PlayerDeath);
    }

    void OnRespawn(object arg) { _triggered = false; } // 重生后复位，可再次触发
}
```

> **关键区别**：`尖刺`等是场景内临时对象，必须 `OnEnable`/`OnDisable` 成对订阅/退订；`GameManager` 是常驻对象，`Awake` 订阅一次即可。

## 7. 一次"死亡"的完整链路

```
尖刺碰到玩家
  → Spike 广播 PlayerDeath
  → GameManager.OnPlayerDeath（死亡次数 +1）
  → GameManager 广播 DeathCountChanged(次数)
  → HUD.OnDeathCount 刷新右上角数字
  → GameManager 播死亡动画（Animation Event 回调）
  → 重生后广播 PlayerRespawned（关卡机关重置）
```

## 8. 注意！

1. **忘记退订** → 对象销毁后仍会收到事件 / 内存泄漏。
2. **重复订阅** → 在 `OnEnable` 订阅却没在 `OnDisable` 退订，反复开关对象会叠加，回调被触发多次。
3. **强转错类型** → 把 `arg` 当成 `Vector3` 实际是 `int`。务必对照 [[代码与命名规范]] 1.1 参数约定表。
4. **handler 里抛异常** → 会中断后续订阅者。
5. **新增事件只改枚举、不改参数表** → 别人不知道 `arg` 传什么类型。
